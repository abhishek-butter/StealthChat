2. Jargon Buster: Every Networking Term Explained Simply

Here are the fundamental networking concepts used in this project, explained without confusing textbook clutter:

🔌 Socket
The software endpoint that lets programs talk over a network. Think of it as a virtual plug socket connecting two computers over the internet.
🚪 Port (e.g. 8189 vs 8080)
A logical door number on your computer. IP address gets data to the machine; the Port number tells the OS which specific application should receive it.
🤝 TCP vs UDP
TCP is connection-oriented and reliable (3-way handshake, in-order packets, auto-retransmits). UDP is fast but fire-and-forget (packets can drop or get scrambled). Chat apps must use TCP.
🧵 Concurrency & Multithreading
If a server has only 1 thread, it can only talk to 1 user at a time (all others freeze). We spawn worker threads (ClientHandler) so hundreds of users can talk at once.
⚡ WebSockets (RFC 6455)
Unlike normal HTTP where the browser asks and waits, WebSockets establish a permanent, 2-way highway. The server can push messages instantly to the browser with only 2–10 bytes of frame overhead.
📣 Pub/Sub (Publish-Subscribe)
A messaging pattern where senders "publish" messages to a topic (like /topic/101) and all subscribed users receive it automatically without knowing who the sender is directly.
🎟️ JWT (JSON Web Token)
A cryptographically signed identity badge. When a user logs in, they get a JWT token. They show this token on every WebSocket connection to prove who they are without querying passwords.
🛡️ Channel Interceptor
A security gatekeeper inside the WebSocket pipeline. When a user tries to subscribe to a chat room, the interceptor checks the database: if you're not in the group, it drops your packet.
💓 Heartbeat & Cache TTL
Clients send a ping every 15s. If the server doesn't get a ping within 30s (Time-To-Live), it knows the user lost power or signal and marks them OFFLINE.
🔁 Idempotency & Deduplication
On mobile connections, duplicate packets happen when ACKs drop. The client assigns a UUID (clientMsgId); the server remembers it for 5 min and ignores duplicate copies.
📑 BroadcastChannel API
A browser feature allowing multiple tabs to talk directly to each other without pinging the server. If Tab 1 reads a message, Tab 2 updates its blue ticks instantly.
📦 IndexedDB & Service Worker
IndexedDB is an in-browser database caching chat history locally. Service Worker intercepts offline requests and background-syncs queued messages once Wi-Fi returns.
STEALTHCHAT TEAM GUIDE SECTION 3: THE CORE NOVELTY

3. The Core Novelty: Steganographic Carrier Image Encryption

⭐ THIS IS THE MOST IMPORTANT SECTION OF THE PROJECT!
The entire grade depends on explaining why our project is novel and innovative compared to other chat apps.

The Critical Flaw of Apps like WhatsApp, Signal, and Telegram:

  • WhatsApp and Signal use state-of-the-art End-to-End Encryption (E2EE) such as AES-256-GCM.
  • However, the ciphertext itself is loudly visible on the network wire. When encrypted text traverses an ISP or firewall, it has high Shannon entropy (it looks like random high-entropy noise).
  • Deep Packet Inspection (DPI) appliances and network administrators immediately detect that an encrypted, secretive conversation is happening. In authoritarian regions, college networks, or corporate firewalls, encrypted streams are routinely blocked, flagged, or tracked.

Our Novel Innovation ("StealthChat" Protocol):

Instead of sending obvious ciphertext that triggers alarms, our application invents a Zero-Knowledge Steganographic Carrier Channel:

  1. Procedural Canvas Generation: When a user turns on "Stealth Mode", the browser generates a unique, random color gradient on an HTML5 <canvas> element. (Zero hardcoded images; every message has a unique visual fingerprint).
  2. Binary Stream Conversion: The secret message is converted into UTF-8 binary bits, terminated with a 16-bit null terminator (0000000000000000).
  3. Bitwise Least Significant Bit (LSB) Encoding: We iterate over the Red, Green, and Blue bytes of the pixel data (skipping Alpha to keep opacity 100%), and replace the lowest bit:
    // The Core Bitwise Algorithm in index.html: data[i] = (data[i] & ~1) | parseInt(secretBit);
  4. Imperceptible Visual Variance (≤ 0.39%): Changing only the lowest bit changes a color channel by at most 1 out of 255. The human visual cortex cannot perceive this tiny shift, and computer heuristic filters see standard pixel noise.
  5. Network Camouflage: The WebSocket transmits a legitimate image/png Base64 data payload. To network sniffers (Wireshark), firewalls, and database logs, it looks 100% like someone simply shared a random piece of digital artwork!
  6. Client-Side GPU Extraction: The recipient receives the image and decrypts it purely inside their local canvas buffer. The server never sees the plaintext or the keys.

STEALTHCHAT TEAM GUIDE SECTION 4: WHAT WE BUILT (CODE & ARCHITECTURE)

4. What Did We Actually Build? (The Architecture Roadmap)

Our project consists of two distinct engineering milestones:

Phase 1: The Raw Java Socket Prototype (Computer Networks Foundation)

  • ChatServer.java: Binds a raw TCP socket on port 8189. Runs an infinite loop accepting connections via serverSocket.accept(). Dispatches each client to a ClientHandler thread. Maintains a thread-safe synchronized(clientWriters) set to broadcast text to all connected users.
  • ChatClient.java: Terminal console client. Uses two threads: main thread reads keyboard input, listener thread reads incoming socket text.
  • ChatClientGUI.java: Desktop graphical client built with Java Swing. Demonstrates how the Event Dispatch Thread (EDT) updates the window while a background worker thread listens to the socket to prevent UI freezing.

Phase 2: The Enterprise StealthChat Web Application (Modern Real-Time Architecture)

Built with Spring Boot 3.2.3, Java 17, and HTML5/Vanilla JS:

  • WebSockets & STOMP Broker (WebSocketConfig.java): Enables the /ws-chat endpoint with SockJS and configures the in-memory message broker on /topic.
  • Packet-Level Security Interceptor (WebSocketSecurityChannelInterceptor.java): Validates JWT on CONNECT and verifies user membership in GroupMembershipRepository on SUBSCRIBE.
  • Idempotency & Deduplication Engine (IdempotencyService.java): Sliding 5-minute cache that drops duplicate packets carrying the same client-generated UUID (clientMsgId).
  • Presence & Heartbeat Engine (PresenceService.java): Maintains user online status with a 30-second TTL cache, supported by a @Scheduled background eviction sweep every 5 seconds.
  • Delivery & Read State Machine (ChatController.java): Handles /app/chat.sendMessage, /app/chat.ackDelivery, and /app/chat.ackRead to power the dynamic WhatsApp-style tick indicators.
  • Offline Resilient Client (index.html + sw.js): Stores room messages in IndexedDB (StealthChatDB) and uses a Service Worker with the Background Sync API to queue and auto-flush messages when disconnected.

STEALTHCHAT TEAM GUIDE SECTION 6: VIVA QUESTIONS & MODEL ANSWERS

6. Teacher Viva / Exam Defense Handbook

Here are the exact questions teachers love to ask, along with the high-scoring answers:

❓ Q1: "Why did you use TCP instead of UDP for the chat application?"
Answer: "Instant messaging requires absolute reliability and sequential ordering. TCP provides a 3-way handshake, packet sequence numbers, error checksums, and automatic retransmissions. If we used UDP, packets could be lost or arrive scrambled—altering conversation meaning (e.g., dropping critical numbers or words)."
❓ Q2: "How is WebSockets different from traditional HTTP polling?"
Answer: "In HTTP polling, the client repeatedly sends requests every few seconds. Each request incurs 500B to 2KB of redundant header overhead and high server CPU load. WebSockets performs an initial HTTP 101 Upgrade handshake, then establishes a persistent, full-duplex TCP stream with a framing overhead of only 2 to 10 bytes."
❓ Q3: "What happens if a user's phone battery dies? How does the server know they are offline?"
Answer: "An abrupt power loss or signal drop doesn't send a clean TCP FIN packet. To solve this, we implemented a Heartbeat & TTL Cache in PresenceService.java. Clients ping /app/chat.heartbeat every 15s. If no ping is received within 30 seconds (TTL), a background @Scheduled sweeper automatically evicts the user and broadcasts OFFLINE to the channel."
❓ Q4: "What prevents duplicate messages when a mobile user clicks Send multiple times on a bad connection?"
Answer: "We implemented Client-Side Idempotency. The browser generates a unique UUID (clientMsgId) before transmitting. The backend's IdempotencyService.java maintains a 5-minute sliding TTL cache. If a duplicate packet arrives with the same ID, the server drops the duplicate database write and merely returns the existing ACK."
❓ Q5: "How do you stop unauthorized users from snooping on private groups?"
Answer: "We built a WebSocketSecurityChannelInterceptor.java. When a client sends a STOMP CONNECT frame, we validate their signed HMAC-SHA256 JWT. When they send a SUBSCRIBE frame to /topic/{roomId}, the interceptor checks GroupMembershipRepository. If they are not an authorized member, the subscription packet is rejected."
❓ Q6: "What is your project's novelty and how does the image encryption work?"
Answer: "Our novelty is Steganographic Carrier Encryption to defeat Deep Packet Inspection (DPI). While WhatsApp and Signal send obvious ciphertext that firewalls flag, we generate a dynamic HTML5 Canvas artwork and encode secret bits into the Least Significant Bit (LSB) of the RGB channels using (pixel & ~1) | bit. The maximum color variance is under 0.39%—invisible to the human eye. To the network, it looks like innocent PNG image sharing."
❓ Q7: "What happens when the client is completely offline?"
Answer: "We built an Offline-First Architecture using IndexedDB (StealthChatDB) and a Service Worker (sw.js). Outgoing messages are queued in an IndexedDB outbox with a 🕒 pending icon. When the network reconnects, the Service Worker Background Sync triggers and automatically flushes the queue over the WebSocket."
❓ Q8: "Why did you use IndexedDB instead of localStorage?"
Answer: "localStorage is synchronous, blocks the browser UI thread, and is capped at 5MB with strings only. IndexedDB is an asynchronous, transactional, indexed NoSQL datastore that handles large binary blobs (like our steganographic canvas images) and complex queries without freezing the page."
