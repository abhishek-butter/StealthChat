2 The 30-Second Elevator Pitch

What to say when an examiner asks: "What did you actually build?"

"Standard encrypted apps like WhatsApp or Signal encrypt message contents, but their scrambled ciphertext produces maximal Shannon entropy (7.98 bits/byte). This random noise acts like a beacon to Deep Packet Inspection (DPI) middleboxes, alerting firewalls that secret communication is happening.

In StealthChat, we solve this metadata leakage paradox. Instead of sending raw ciphertext, our client dynamically paints an organic gradient on an HTML5 canvas and embeds the confidential message into the image's lowest color bits (LSB) over a high-throughput Spring Boot WebSocket. Intermediate firewalls only see routine PNG images passing through, achieving zero metadata leakage with sub-5ms delivery."

3 Jargon Buster: Every Technical Term in Plain English

1. Deep Packet Inspection (DPI) Network Security
→ Analogy: An airport X-ray scanner opening luggage instead of just reading baggage tags.
Standard firewalls only check IP headers (where packets come from and go). DPI firewalls inspect the actual packet content. If they detect encrypted patterns where normal web pages should be, they throttle or drop the connection.
2. The Cryptographic Metadata Leakage Paradox Core Thesis
→ Analogy: Walking into a library wearing a ski mask and whispering. You haven't revealed what you're saying, but you've already attracted security.
The stronger your encryption (e.g., AES-256), the more random your data looks. Firewalls calculate randomness (Shannon Entropy). Plain text has an entropy of ~4 bits/byte; pure ciphertext has an entropy of ~7.98 bits/byte. This mathematical randomness screams to firewalls that you are hiding something.
3. Procedural Steganography vs. Cryptography Innovation
→ Cryptography hides the meaning. Steganography hides the existence.
Traditional steganography hides data inside a static image (like a downloaded dog photo), but static images have fixed hashes that firewalls can blacklist. Procedural steganography means our JavaScript code paints a brand-new, unique gradient canvas using random seeds for every single message. Every packet has a completely unique image hash.
4. Least Significant Bit (LSB) Modulation Encoding
→ Analogy: Changing a paint color from 99.6% red to 100% red. Nobody can see it.
Every pixel has Red, Green, and Blue values from 0 to 255 (8 binary bits). The 8th bit (the Least Significant Bit) only alters brightness by 1 unit out of 255 (a 0.39% shift). We replace that 8th bit with bits from our secret text.
5. CIE ΔE* (Delta E) & JND Perceptual Metric
→ Analogy: A scientific ruler measuring whether human eyes can notice a color change.
Just Noticeable Difference (JND) is defined by color scientists as ΔE* < 1.0. If ΔE* is less than 1, human eyes cannot see any change. StealthChat achieved ΔE* = 0.28, proving total visual invisibility.
6. PSNR & SSIM Metrics Image Fidelity
→ Quality benchmarks for signal processing.
PSNR (Peak Signal-to-Noise Ratio): Measured in decibels (dB). Above 40 dB is considered indistinguishable from original. StealthChat scored 57–75 dB.
SSIM (Structural Similarity Index): Measures structural distortion from 0 to 1. StealthChat scored 0.998+.
7. RFC 6455 WebSockets vs. HTTP Polling Transport Protocol
→ Polling = Calling someone every 10 seconds asking "Did you speak yet?". WebSocket = An open phone line.
HTTP polling forces the browser to send 850–1200 byte HTTP headers and execute repeated TCP 3-way handshakes for every check. WebSockets upgrade the connection once (HTTP 101) and transition to full-duplex frames with just 2 to 6 bytes of header overhead.
8. 4-Stage Deterministic State Machine Reliability
→ The blue-tick progression WhatsApp uses, but engineered with formal finite-state mechanics.
• Pending (🕒): Buffered in browser IndexedDB before network dispatch.
• Sent (✓): Ingested by Spring Boot server and committed to SQL database.
• Delivered (✓✓): Recipient's WebSocket client received frame and sent back ACK.
• Read (✓✓ Blue): Recipient focused window and active viewport rendered message.

6 Viva Defense Master Cheat Sheet (The 7 Killer Questions)

Q1 Why use steganography if HTTPS / TLS encryption already exists?
"HTTPS protects message content, but TLS packet lengths, handshake signatures, and ciphertext exhibit near-maximal Shannon entropy (7.98 bits/byte). In monitored or adversarial networks with TLS-bumping proxies, firewalls detect this high-entropy randomness and automatically throttle or drop the packets. Steganography provides plausible deniability: to the firewall observer, the user is simply sending a benign PNG image."
Q2 Why not use an existing JPEG photo as the cover image?
"Two reasons, sir: First, JPEG uses lossy compression (DCT quantization), which corrupts the least significant bits during transit. Second, reusing static images produces known cryptographic file hashes that middleboxes can catalog and blacklist. StealthChat procedurally synthesizes a fresh gradient canvas on every message, guaranteeing zero static hash fingerprints."
Q3 What happens if the recipient is offline when a message is sent?
"The sender's client stores the message locally in browser IndexedDB with status PENDING. The Spring Boot server receives it and persists it in our SQL database. When the recipient reconnects, their client loads the channel history via REST and immediately dispatches a background delivery ACK (/app/chat.ackDelivery), transitioning the status to DELIVERED."
Q4 How does the receiver know where the hidden message stops?
"We deliberately do not send a message length header because that would leak structural metadata to DPI sniffers. Instead, our encoder appends a 16-bit null delimiter (0000000000000000) to the bitstream. The recipient's decoding loop reads sequential LSBs until it encounters 16 consecutive zero bits, and cleanly terminates."
Q5 Why did you transition from Java Sockets (Phase 1) to Spring Boot WebSockets (Phase 2)?
"Phase 1 used a thread-per-client blocking I/O model (ServerSocket.accept()). Each thread consumed ~1MB of OS stack memory, causing JVM heap limits around 4,000 users. More critically, web browsers cannot open raw TCP sockets due to security sandboxing. In Phase 2, RFC 6455 WebSockets and Spring Boot STOMP pub/sub provided native browser compatibility, JWT authorization interceptors, and non-blocking event-driven scalability."
Q6 What is the computational overhead of LSB encoding on the client?
"Because we utilize HTML5 Canvas getImageData() and typed bitwise arrays (Uint8ClampedArray), encoding a 1KB text payload into a 250×100 canvas takes less than 1.8 milliseconds on modern mobile or desktop browsers, causing zero perceptible lag to the user."
Q7 What major engineering bugs did you encounter during implementation?
"We documented three critical challenges in Section VIII: 1. Port Collision: Both raw TCP and Tomcat attempted binding to 8080; resolved by isolating raw sockets to 8189.
2. Circular Dependency: WebSocketConfig → SecurityInterceptor → PresenceService → SimpMessagingTemplate; resolved using @Lazy injection and Spring's ApplicationEventPublisher.
3. Asynchronous DOM Bleeding: Switching chat rooms rapidly caused late-arriving REST payloads from Room A to show in Room B; resolved using monotonic currentRoomRequestId tokens."
